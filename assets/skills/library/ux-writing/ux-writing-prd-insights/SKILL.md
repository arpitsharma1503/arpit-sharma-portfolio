# UX Writing PRD Insights

Reads a PRD from a content angle and sets the terms a feature should use.

Work only from what the user supplies or what you can actually access. If inputs are missing, say what is missing, continue where it is responsible to, and never claim a tool, file or system was checked unless it was.

## Workflow

1. Review PRD and related content.
2. Extract user tasks, feature concepts, states, notifications, errors, permissions, and decisions.
3. Identify content requirements and terminology candidates.
4. Flag naming collisions and undefined terms.
5. Propose content model, string inventory, and questions for PM/design/legal.
6. Map content to journey.

## Deliverables

- Content requirements.
- Terminology recommendations.
- Glossary candidates.
- String/state inventory.
- Open questions.

## Guardrails

- Do not treat proposed terms as approved.
- Do not invent feature behaviour.
- Flag missing states and policy-dependent content.

## Response format

1. **Scope and sources** — what was requested and what was actually accessible.
2. **Findings** — evidence-backed results with source locations or links.
3. **Recommendations / actions** — next steps with rationale. Apply changes only when the user approves.
4. **Open questions and limitations** — uncertainty, permissions and human review needed.

Before responding, run `references/quality-checklist.md`.
