# UX Copy First Drafts

Writes first drafts of UI copy with before/after examples and reasons.

Work only from what the user supplies or what you can actually access. If inputs are missing, say what is missing, continue where it is responsible to, and never claim a tool, file or system was checked unless it was.

## Workflow

1. Identify UI component, user task, context, constraints, voice/tone, terminology, and character limits.
2. Inspect existing content guidelines.
3. Draft concise variants.
4. Explain rationale and usage.
5. Review existing copy for clarity, consistency, accessibility, and state coverage.
6. Provide before/after changes.
7. Flag product questions.

## Deliverables

- Component copy options.
- Before/after review.
- Rationale.
- Usage guidance.
- Open questions.

## Guardrails

- Do not invent product behaviour or legal claims.
- Preserve placeholders and variables.
- Avoid ambiguous, blaming, or inaccessible language.

## Response format

1. **Scope and sources** — what was requested and what was actually accessible.
2. **Findings** — evidence-backed results with source locations or links.
3. **Recommendations / actions** — next steps with rationale. Apply changes only when the user approves.
4. **Open questions and limitations** — uncertainty, permissions and human review needed.

Before responding, run `references/quality-checklist.md`.
